{{ if $zh }}把 PPO 的 batch 用对{{ else }}Get PPO's batch right{{ end }}{{ if $zh }}batch = 环境数 × 每环境步数。还要看重置是否同步，以及 minibatch 和学习率是否随环境数调整。改动最便宜，也最常做错。{{ else }}Batch = environment count × steps per environment. Also check whether resets are synchronized, and whether minibatches and learning rates change with environment count. These are the cheapest changes, and the ones most often done wrong.{{ end }}Rudin · Andrychowicz · DD-PPO · Mayor · Staggered Resets · Hilton · Beukman
{{ if $zh }}多策略：用种群换多样性{{ else }}Multiple policies: diversity through a population{{ end }}{{ if $zh }}一张卡上同时训练几个到几十个策略，互相借数据，或者定期淘汰差的、变异好的。买的是探索的多样性，代价是更多算力和代码复杂度。{{ else }}Train several to dozens of policies on one GPU. Let them borrow data, or periodically discard poor ones and mutate good ones. This buys exploration diversity at the cost of more compute and more complex code.{{ end }}DexPBT · SAPG · EPO
{{ if $zh }}改起点：重置分布与课程{{ else }}Change the starting point: resets and curricula{{ end }}{{ if $zh }}让难的状态直接出现在 batch 里：从生成的抓取态、演示的中间态或接近目标的状态开始回合，再按成功率挑起点。对长程接触任务效果最大。{{ else }}Put difficult states directly into the batch: start episodes from generated grasp states, intermediate demonstration states or states near the goal, then choose starting points by success rate. This helps most on long-horizon contact tasks.{{ end }}OmniReset · SGS · DemoStart · RFCL · DextrAH-G/RGB · CSRL
{{ if $zh }}off-policy 在海量并行下复活{{ else }}Off-policy returns with massive parallelism{{ end }}{{ if $zh }}用回放池重复利用数据，配上大 batch、分布式 critic 和归一化，让 SAC/TD3 在几千个环境下比 PPO 更快。{{ else }}Reuse data through replay buffers, with large batches, distributed critics and normalization, making SAC/TD3 faster than PPO with thousands of environments.{{ end }}PQL · PQN · FastTD3 · FastSAC · FlashSAC/WarpSAC · REPPO
